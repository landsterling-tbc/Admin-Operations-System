# نظام العمليات الإدارية

نظام إداري (سيارات، وقود، عهدة نقدية، مصروفات) مبني بملفات ثابتة بالكامل — `index.html` / `style.css` / `script.js` / `config.js` — بدون أي أدوات بناء وبدون أي سيرفر إضافي، ومتصل بـ Supabase (قاعدة بيانات + RLS). نظام الدخول مخصص بالكامل (RPC + JWT موقّع)، مش Supabase Auth.

## 1) إعداد قاعدة البيانات (مرة واحدة، بالترتيب بالظبط)

كل حاجة في `database/schema.sql`. لو المشروع جديد تمامًا شغّل الملف كله من الأول للآخر بالترتيب. لو عندك نسخة سابقة، الأقسام المرقّمة (9، 10) مصممة تتشغّل فوق نسخة موجودة بالفعل.

**⚠️ القسم 10 لازم يتشغّل على خطوتين منفصلتين:**

1. شغّل السطر ده **لوحده** الأول (قسم 10.1):
   ```sql
   alter type public.user_role add value if not exists 'admin';
   ```
2. بعد ما ينجح، شغّل باقي القسم 10 (10.2 لحد الآخر) مع بعض.
3. فعّل pgjwt + سرّ التوقيع (قسم 10.7): من **Project Settings → API → JWT Settings** انسخ قيمة **JWT Secret**، وشغّل:
   ```sql
   select vault.create_secret('PASTE_YOUR_PROJECT_JWT_SECRET_HERE', 'app_jwt_secret');
   ```
4. أنشئ أول حساب Super Admin (قسم 10.8) — استبدل الاسم/الإيميل/كلمة مرور مؤقتة قوية وشغّل الاستعلام، ثم سجّل دخولك بيها فورًا وغيّرها من "تغيير كلمة المرور".

## 2) الأدوار

| الدور | يقدر يعدّل |
|---|---|
| مدير النظام (`super_admin`) | كل حاجة، بما فيها حسابات النظام وسجل العمليات وأصول تقنية المعلومات |
| أدمن (`admin`) | السيارات، الوقود، العهدة النقدية، المصروفات — مش حسابات النظام ولا سجل العمليات ولا أصول تقنية المعلومات |
| دعم تقني (`it_support`) | أصول تقنية المعلومات فقط (لابتوبات، إيميلات، أرقام SIM، أجهزة لوحية، كتالوج) — القائمة الجانبية بتاعته مقتصرة على الرئيسية + أصول تقنية المعلومات بس |
| مدير (`manager`) | عرض فقط، من غير تعديل |

الفرض الفعلي لكل ده من RLS في قاعدة البيانات نفسها — إخفاء الأزرار في الواجهة مجرد تحسين تجربة استخدام.

## 3) الوحدات الحالية

| الوحدة | الوصف المختصر |
|---|---|
| لوحة الرئيسية | إحصائيات عامة + رسوم بيانية + تنبيهات (انتهاء تفويض سيارة، رصيد عهدة منخفض) |
| السيارات | سجل + بحث/فلترة + استيراد Excel + تفاصيل (ملخص وقود، سجل عمليات) |
| الوقود | معاملات تعبئة الوقود مرتبطة بسيارة، إلغاء (Void) بدل حذف |
| العهدة النقدية | صندوق عهدة عام واحد (مش لكل موظف) — تمويل/تصفير/إغلاق |
| المصروفات | مرتبطة بصندوق العهدة النشط + فئة مصروف |
| أصول تقنية المعلومات | لابتوبات، إيميلات، أرقام SIM، أجهزة لوحية، كتالوج لابتوبات — كل نوع بصفحة خاصة به + تقرير فرعي في التقارير |
| التقارير | تقارير قابلة للتصدير CSV لكل وحدة، بما فيها تقرير عام + فرعي لكل نوع أصل تقني |
| سجل العمليات | تتبّع كل عملية حساسة (Super Admin فقط) |
| حسابات النظام | إدارة حسابات الدخول والأدوار (Super Admin فقط) |
| البحث الشامل | بحث فوري في السيارات والمواقع من التوب بار |

## 4) ميزات أُزيلت من الواجهة (موجودة في قاعدة البيانات لكن غير مستخدمة)

بناءً على طلب صريح من المستخدم (أغسطس 2026) — بما إن الشركة مش هتضيف موظفين رسميًا للنظام ولإن الإدارات مختلفة وكل حاجة هتتسجل كنص حر:

- **صفحة "الموظفون"** بالكامل (عرض/إضافة/تعديل/تعطيل) — اتشالت من القائمة الجانبية ومن الكود.
- **حقل "التخصيص الرسمي"** في فورم السيارة (كان بيربط السيارة بموظف من جدول `employees`) — اتشال، وبقي الاعتماد بس على "اسم المستخدم الفعلي" (نص حر).
- **تبويب "تاريخ التنقلات"** في تفاصيل السيارة (كان بيسجّل كل مرة يتغيّر فيها التخصيص الرسمي) — اتشال بالكامل.
- شيت "الموظفون" من تصدير النسخة الاحتياطية، ونتيجة "الموظفون/السائقون" من البحث الشامل.

**قاعدة البيانات لسه فيها** جدول `employees`، وعمود `vehicles.current_employee_id`، وجدول `vehicle_assignments` — ملهمش أي مستهلك من الواجهة دلوقتي، بس اتسابوا زي ما هم (مفيش `DROP`) عشان لو احتجنا نرجّع الميزة تاني في المستقبل. لو حبيت ترجّعها:

1. رجّع من كود المصدر (git history) أو اطلب من Claude يبني تاني: حقل `vehicle-form-employee` في الفورم، عمود "التخصيص الرسمي" في جدول السيارات، تبويب "تاريخ التنقلات"، وصفحة "الموظفون" مع الـ CRUD بتاعتها.
2. البنية في قاعدة البيانات (`employees`, `vehicle_assignments`, `vehicles.current_employee_id`) جاهزة زي ما هي، مفيش حاجة تتعمل فيها.

## 5) الاستضافة عبر GitHub Pages

المشروع جاهز للنشر كما هو — الملفات نسبية المسار، فبيشتغل من أي مسار (روت أو مجلد فرعي).

1. ارفع محتوى هذا المجلد لريبو على GitHub (`supabase/` القديم ملغى، ممكن تمسحه).
2. **Settings → Pages → Build and deployment → Source**: اختار **Deploy from a branch**.
3. اختار الفرع (`main`) والمجلد `/ (root)`، واحفظ.

ملف `.nojekyll` بيمنع GitHub من معالجة الموقع كـ Jekyll site.

### ملاحظة أمان

`SUPABASE_ANON_KEY` في `config.js` مقصود إنه يكون عام/ظاهر — طبيعي وآمن، الحماية الفعلية من RLS. **مفيش أي مفتاح سرّي (service_role) في أي ملف من ملفات المشروع، ولا لازم يكون فيه أبدًا** — كل العمليات الحساسة (تسجيل الدخول، تغيير الباسورد، إدارة الحسابات) بتتم عبر RPC functions بمفتاح anon بس، وبتتحقق من الصلاحيات بنفسها جوا قاعدة البيانات.
